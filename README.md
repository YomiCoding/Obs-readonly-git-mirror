# Data Transmission

用一次性配置码绑定收件服务器后，每 10 秒把发给你的内容（整理好的笔记页，连同图片、PDF 等原文件）自动收进你的 Obsidian 库。条目只会被新增到库里；你收到并校验之后，服务端可以删除它那一份。

## 收件箱模式

### 绑定设备

服务端会给你一个一次性的**配置码**（很快过期，只能用一次）。把它粘贴到 设置 → Data Transmission → **配置码**。插件用它换取一个设备令牌，只保存服务器地址、令牌和设备 id，不保存配置码。每台电脑单独绑定；每台设备有自己的令牌，可以单独解除绑定（命令面板：**解除本设备绑定**，或者在服务端操作）。

如果这个库以前用过镜像模式，切换过来时会删掉你从没改过的镜像文件和本地 `.git` 文件夹；你改过的文件和你自己的笔记都会保留。弹出的提示会告诉你删了几个、留了几个。

### 一次同步做了什么

启动时执行一次，之后每 10 秒一次：

1. 补发上次没发出去的确认。
2. 列出等待本设备接收的条目。
3. 把每个文件下载到临时的 `.part` 文件，改名放到位，再读回来校验 SHA-256。页面引用的其他文件先写入，页面最后写入。
4. 先把条目记进本地账本（保存在 `data.json`），然后才确认收到。

## 共享知识库（可选）

如果服务端把你加入了某个共享知识库，每次收件之后插件还会把这个库镜像到库里单独的文件夹（文件夹名由服务端给出），和收件箱的文件分开。不需要另外绑定；设置里的 **同步共享知识库** 可以关掉。

- **镜像**：服务端新增的条目会出现，服务端删除的条目会从本地消失。清单带 ETag，没有变化时不下载任何东西。
- **只动自己写的文件**：插件在 `data.json` 里记一本共享账本（路径 → 写入时的 SHA-256）。只有账本里、位于共享文件夹内、而且内容没被改过的文件，才会被更新或删除。你改过的文件不会被覆盖或删除，它变成你自己的笔记；你的其他笔记和收件箱文件永远不动。
- **在 Obsidian 里删除**：删掉一篇共享页面，就是向服务端申请删除这一条。服务端决定是否接受（通常只有贡献者或管理员可以）：接受了，所有成员那里都会删除；不接受，页面会被放回并提示。只删了页面引用的文件（图片、PDF 等）不算申请，会被放回。一次消失很多页面（比如删除或移动了整个文件夹）会被当作误删，全部放回，不上报。
- **离开共享库**（服务端不再返回这个库，或者你关掉了开关、解除了绑定）：删除没改过的共享副本，保留改过的，并提示一次。
